# fsearch — поиск по файлам: по именам и по содержимому

Быстрый полнотекстовый поисковик для локальных дисков на Rust. Ищет не только по названиям,
но и **внутри файлов**: Word, Excel, PowerPoint (и их старые форматы), PDF, OpenDocument, RTF, обычный текст.
Понимает русский и английский: учитывает словоформы («договор» найдёт «договоров», «report» — «reports»),
не различает «е» и «ё», умеет искать по подстроке в имени и с опечатками.

```
> fsearch search кракозябровая
  1. Договор аренды.docx  37,6 КБ · 15.03.2026 12:04
     D:\Договоры\Договор аренды.docx
     …по адресу: город Казань, улица Кракозябровая, дом 7. Ежемесячная арендная плата…
  2. Продажи 2024.xlsx  7,0 КБ · 20.05.2026 09:10
     D:\Отчёты\Продажи 2024.xlsx
     [Лист «Продажи»] …Тюльпаны голландские 120 45678.5 INV-774411…
```

## Что читается

| Формат | Расширения | Что извлекается |
|---|---|---|
| Word | `.docx .docm .dotx .dotm` | текст, таблицы, колонтитулы, сноски, примечания, текстовые рамки, свойства (заголовок, автор, ключевые слова) |
| Word 97–2003 | `.doc .dot` | основной текст, таблицы, колонтитулы, сноски |
| Excel | `.xlsx .xlsm .xltx .xltm` | все листы, значения, **даты** (ищутся и как `15.03.2024`, и как `2024-03-15`), комментарии и примечания, текст в фигурах |
| Excel 97–2003, xlsb | `.xls .xlt .xlsb` | все листы, значения |
| PowerPoint | `.pptx .pptm .potx .potm .ppsx .ppsm` | текст слайдов **в порядке показа**, таблицы, заметки докладчика, комментарии, SmartArt |
| PowerPoint 97–2003 | `.ppt .pps .pot` | текст слайдов и заметок |
| OpenDocument | `.odt .ods .odp` (+шаблоны) | текст, листы, слайды |
| PDF | `.pdf` | текст постранично (если в PDF есть текстовый слой) |
| RTF | `.rtf` | текст (в т. ч. кириллица в cp1251 и `\uNNNN`) |
| Текст и код | `.txt .md .csv .log .json .xml .html .py .rs …` и любые файлы, похожие на текст | UTF-8, UTF-16, **cp1251, cp866, KOI8-R** определяются автоматически; HTML очищается от тегов |

Формат определяется **по содержимому, а не по расширению**: HTML, сохранённый как `.xls`, RTF под видом `.doc`,
документ OpenDocument с расширением `.docx` читаются правильно.

Для Excel, PowerPoint и PDF результат показывает, **где именно** найдено: `[Лист «Продажи»]`, `[Слайд 3]`, `[Стр. 12]`.

Файлы, защищённые паролем, и файлы, которые не удалось прочитать, всё равно находятся по имени; в отчёте об
индексации они перечислены отдельно.

## Установка

Нужен [Rust](https://rustup.rs) (на Windows — вместе с «Build Tools for Visual Studio», rustup предложит их сам).

```powershell
git clone https://github.com/horv1tz/file_search
cd file_search
cargo build --release
# готовый файл: target\release\fsearch.exe
```

Готовые сборки для Windows/Linux/macOS собирает GitHub Actions (вкладка *Actions* → последний запуск → *Artifacts*).

## Быстрый старт

```powershell
# 1. Проиндексировать диск (повторный запуск обновляет только изменившееся — обычно секунды)
fsearch index D:\

# 2. Искать
fsearch search договор аренды
fsearch search "срок действия" --ext docx,pdf
fsearch search отчёт --name                      # только по именам файлов

# 3. Или пользоваться из браузера
fsearch serve --open

# 4. Держать индекс свежим автоматически
fsearch serve --watch D:\ --open                 # веб-интерфейс + слежение за диском
fsearch watch D:\                                # только слежение
```

Подсказка по любой команде: `fsearch --help`, `fsearch search --help`.

## Язык запросов

| Запрос | Значение |
|---|---|
| `договор аренды` | оба слова (в имени, содержимом или свойствах) |
| `"срок действия"` | точная фраза |
| `отчёт -черновик` | исключить слово |
| `догов*` | слова, начинающиеся с «догов» |
| `аренда~` &nbsp; `аренда~2` | с опечатками (1 или 2 правки) |
| `аренда OR лизинг` | любое из слов |
| `name:смета` | только в имени файла (в том числе подстрока: `name:мет`) |
| `content:смета` | только в содержимом |
| `path:бухгалтерия` | в имени или пути к папке |
| `ext:docx,xlsx` | только эти типы файлов |

Фильтры командной строки: `--ext docx,pdf`, `--in D:\Работа` (можно несколько раз), `--min-size 10K`, `--max-size 5M`,
`--after 2024-01-01`, `--before 31.12.2024`, `--sort newest|oldest|largest|smallest|relevance`, `-n 50 --offset 50`
(страницы), `--json` и `--paths` для скриптов. Запрос можно оставить пустым и искать только по фильтрам:
`fsearch search --ext xlsx --after 2024-06-01 --sort newest`.

Ранжирование: совпадение в имени файла весомее, чем в свойствах, а те — весомее, чем в тексте; короткие
документы с совпадением выше длинных (BM25).

## Команды

| Команда | Назначение |
|---|---|
| `fsearch index ПУТЬ…` | проиндексировать папки/диски; `-x '*.tmp'` — исключения, `--force` — заново, `--errors` — список нечитаемых файлов |
| `fsearch search ЗАПРОС` | найти файлы |
| `fsearch interactive` (`i`) | интерактивный поиск: вводите запросы, `:open 2` открывает файл, `:dir 2` показывает его в проводнике |
| `fsearch serve` | веб-интерфейс на `http://127.0.0.1:7878` (`--port`, `--open`, `--watch ПУТЬ`) |
| `fsearch watch ПУТЬ…` | следить за папками и обновлять индекс при изменении файлов |
| `fsearch stats` | сколько файлов в индексе, типы, размер индекса, сколько файлов не прочитано |
| `fsearch extract ФАЙЛ` | показать, какой текст извлекается из файла (диагностика: «почему не находится?») |
| `fsearch reset` | удалить индекс |

Индекс хранится в `%LOCALAPPDATA%\file_search\index` (Windows) или `~/.local/share/file_search/index` (Linux);
изменить: `--index-dir ПАПКА` или переменная `FSEARCH_INDEX`.

## Как это работает

- **Индекс** — [tantivy](https://github.com/quickwit-oss/tantivy) (движок уровня Lucene). Один документ на файл; хранятся
  имя, путь, размер, время изменения, извлечённый текст (для фрагментов с подсветкой) и границы листов/слайдов/страниц.
- **Анализ текста** — токены → нижний регистр → «ё»→«е» → стемминг Snowball (русский для кириллицы, английский для латиницы).
  Слова, где стеммер отрезает лишнее («гиппопотам»), находятся и в исходной форме.
- **Инкрементальность** — файл переиндексируется, только если изменились размер или время изменения. Удалённые файлы
  убираются из индекса. Разные корни (`D:\`, `E:\`) не мешают друг другу. Ctrl+C сохраняет сделанное, следующий запуск продолжает.
- **Скорость и память** — чтение файлов идёт параллельно; Office-файлы читаются потоково прямо из zip, без загрузки
  документа целиком. Есть лимиты: до 16 МБ текста из файла (`--max-text-mb`), файлы больше 512 МБ — только по имени
  (`--max-file-mb`). Повреждённый файл не роняет индексацию.
- **Служебное пропускается**: `$RECYCLE.BIN`, `System Volume Information`, `.git`, `node_modules`, блокировки Office (`~$*.docx`),
  `Thumbs.db`, `desktop.ini` (`--no-default-excludes` — не пропускать).

Ориентир (4 ядра, SSD): ~23 500 файлов (docx/xlsx/pptx/txt, 125 МБ) индексируются за 5 с; повторная проверка без
изменений — 1 с; типичный поиск — 3–25 мс; индекс примерно равен по размеру извлечённому тексту.

## Безопасность веб-интерфейса

Сервер слушает только `127.0.0.1`, проверяет заголовок `Host` (защита от DNS rebinding), а кнопки «Открыть»/«В папке»
требуют секретный токен, который выдаётся только странице интерфейса, и работают лишь для файлов из индекса.
Исполняемые файлы (`.exe`, `.bat`, `.ps1`, …) из браузера не запускаются — только «В папке».

## Ограничения

- PDF-сканы без текстового слоя не распознаются (OCR нет).
- Файлы, защищённые паролем, читаются только по имени.
- В `.ppt` (PowerPoint 97–2003) нет разбивки на слайды — текст ищется, но номер слайда не показывается.
- Стемминг иногда даёт «лишние» совпадения на редких словах; для точности используйте `"фразу в кавычках"`.
- Слежение (`watch`) использует события файловой системы; на сетевых дисках они ненадёжны, поэтому раз в 30 минут
  (`--rescan-minutes`) выполняется полная проверка.

## Разработка

```bash
cargo test            # модульные, на реальных файлах (tests/fixtures), крайние случаи, сквозные
cargo run --release -- index ./docs && cargo run --release -- search слово
```

Устройство: `src/extract/` — извлечение текста по форматам, `src/analyzer.rs` — токенизация и стемминг,
`src/indexer.rs` — обход и индексация, `src/query.rs` — язык запросов, `src/search.rs` — поиск и фрагменты,
`src/watcher.rs` — слежение, `src/web/` — веб-интерфейс, `src/main.rs` — командная строка.
